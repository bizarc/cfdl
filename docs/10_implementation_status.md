# CFDL v0.1 — Implementation Status

Status: informative. Every row is verified by compiling a probe model against
the current build rather than read off the grammar — the rows that were wrong
in earlier revisions were wrong because they described intent.

The standard this page holds the language to: **nothing is accepted and
silently discarded.** A construct either works end to end, or it is rejected
with a diagnostic that says so. Several rows below moved from "accepted, does
nothing" to "rejected" for exactly that reason; a construct that quietly does
nothing produces wrong numbers with no signal, which is worse than one that
refuses to compile.

Legend: ✅ works end to end (parse → IR → engine) · 🟡 partial, see notes ·
❌ rejected with a diagnostic.

| entity field rules (`<field> init <expr> next <expr>` in an entity block) | ✅ | a named number per period, owned by the entity it describes and read as `<family>.<entity>.<field>`. `init` is mandatory; `next` sees `prev`, `prev.<family>.<entity>.<field>`, `time.*`, `inputs.*` and curves — never a same-period value, which is what keeps cycles impossible by construction. | — pack-side (`field_name` / `field_init` / `field_next` / `field_every` / `field_from` / `field_to` on a lowering rule) | ✅ | a rule may declare a field on the contract's subject entity; `field_name` must expand to a single identifier, so per-instance fields use `{{contract.suffix_ident}}` |
| `entity <ns> <name> : <Type> { <field> = <lit>, part of <ref>, state <name> }` | ✅ | typed against the active ontology, or the language's base vocabulary when no pack is active. `part of` is optional at every grain. `state` sets the lifecycle state the entity opens in |
| `waterfall <name> on entity <ref> { schedule … from <expr> pay <step> to <ref> = <expr> }` | ✅ | an ordered allocation over a pot, in declaration order; `remaining` draws it down, `paid.<step>`/`owed.<step>` read earlier steps. Schedule is mandatory |
| waterfall step visibility (`E1340`–`E1346`) | ✅ | a step may read an EARLIER waterfall's published series, never its own or a later one's; a stream may read none |
| `account <name> [owed\|due] { owner <ref>  from <expr>  init <expr> }`, `account <name> owed\|due init <expr>` in an entity block, `moves <account>` on a stream, `accrual` / `writeoff` directions | ✅ | the account generalized to the balance an agreement owes or is due (`docs/42`): an entity may own one, streams of all four directions move it (a cash stream by the account's side, an accrual raising and a write-off lowering), a stream reads its OPENING as `prev.<account>`, `init` is the first period's opening and defaults to zero, every movement journaled as `move` naming the stream. Non-cash streams publish as series and enter no cash total, category fold or valuation. `E1378`–`E1382` refuse a non-cash stream that moves nothing or carries a category, an unknown or side-less moved account, and a same-period balance read. Not yet: the relation fold (a container's balance as its members'), the pack side (a master declares the account, a rule's `account` key moves it). Also a declared cash location under the balance law; `from <account>` as a waterfall's pot, `pay <step> to account <name>` credits it, a party-owned account receives that party's allocations, `prev.<account>` is settled history in logic and steps. Balance publishes as a non-cash `account.<name>` series; every movement journaled (`inflow`, `allocate_in`, `allocate_out`). `E1347` refuses an undeclared account payee. BALANCES EXIST ONLY UNDER THE WALK: a model kept on the column order by a forward-reaching read computes none, and the engine warns rather than publishing zeros — see the priced-amounts row for what counts as forward |
| `lifecycle <name> { initial <s>  state a, b  a -> b when <expr> }` | ✅ | the declared finite state machine, core-language; bound with `lifecycle <name>` in an entity block or by the entity's pack type (both is `E1350`). Guarded edges evaluate each period in the from-state, declaration order, one transition per entity per period; self-edges journal and re-anchor; event status writes validated against the relation (refused with the edge named); `E1316`/`E1349`/`E1351`–`E1353` refuse the malformed machine A state may carry ARRIVAL ACTIONS: `on enter <state> { set <field> = <expr> }` for what is true of the state however reached, and an action block on an edge for what is true of the path taken. Entry actions run first, then the taken edge's; a same-field write journals the earlier value `overridden` naming its author. Actions run on every traversal, including one an event's `status` write causes. `set` writes fields and never `status` (`E1358`), the name is entity-relative (`E1359`), and a model augmenting a pack machine may add actions only (`E1357`). A pack declares the same in `types.toml` (`docs/07`). |
| `schedule every <i> from state_enter(<ref>, <state>) for <n> periods` | ✅ | the third anchor: each entry opens its own n-period window during the walk; a re-entered state re-anchors. `E1316`/`E1349` check the anchor's names |
| priced amounts (forward windows in a stream `amount`) | ✅ | a valuation setting a causal amount: evaluated after causal cells settle, downstream readers priced with it, waterfalls run over complete cash; the cycle (logic reading what a priced amount sets) is refused with the path named. A forward window in a GUARD keeps the model on the column order, as does any window bound not provably backward — a bound is proved through numeric literals, `time.t` plus a chain of signed literals, and `max`, `min` and `if` over those |
| `contract` (subject, `term A..B`, `terms { k = v }`) | ✅ | terms feed `{{contract.*}}` lowering templates |
| `contract ... parties { <role> = <party> }` | ✅ | roles are declared by the contract TYPE, not the entity — the same party is lessor in one agreement and lender in another |
| `terms { k = v <unit> }` | ✅ | an optional unit is an ASSERTION about what the number means; the rule declares the truth and a mismatch is `E5024`. Units are never converted |
| `stream ... active in state <name>[, <name>]` | ✅ | lowers to a comparison on the lifecycle state, with the name checked against the owner's declared lifecycle — which a string comparison cannot be |
| `contract effects { ... }` | 🟡 | the block is **required** (`E2002`) but its contents are block-skipped: a stream declared inside is never emitted. Declare streams at top level or via a pack |
| `contract ... parties { ... }` block | ✅ | role-checked against the type's EFFECTIVE roles, resolved through its master chain (`E1320`–`E1322`; an unbound role is refused), and serialized in the IR with the pack's word and the master's beside it (`landlord` / `lessor`) |
| `contract <type> <instance>` (two-token declaration) | ✅ | the instance is its own token and the type is checked where it is written (`E1373`, `E1374`); the fused `cre.lease_unit.tenant_a` spelling is the same declaration. The IR carries `type`, `master`, `contract_name`, `instance` and the terms as typed values |
| `contract tags { ... }` | 🟡 | accepted and discarded; absent from the IR |
| master contract types (`refines`, `abstract`, `type <Master>` in a slice) | 🟡 | twenty-one masters in the language base (Security, Equity, Royalty, Grant and Guarantee reworked from their governing documents against the `docs/41` survey; a line may be allocated or optional, a field may reference a contract or an account, a rule may lower a field and no stream, and a waterfall step may name the contract and allocated line it pays — `credit.participation` and `credit.note` are Security's first two refinements) declare fields, roles, lines and side (`docs/40` §4); refinements inherit them, specialize roles (`landlord refines lessor`) and are checked at pack load (strengthen-only fields, every master role covered, line coverage, template coverage, and every term a rule reads, a validation bounds or a template renders declared as a field). Every shipped pack type declares its terms as fields under the masters' names. The compiler checks a model's terms against the effective roster (`E1371`, `E1372`), checks the type named on a contract or an option (`E1373`, `E1374`), and carries the resolved type, master, instance and parties in the IR. Results publish the contracts in `graph.contracts` with type, master, parties and lowered streams, and each lowered series names its contract (`results_version` 0.13); MCP `lookup` reads each type against its master chain. `type <Master>` and `line <role>` select on slices and authored statement rows, a metric folds a slice as `slice.<name>`, and each lowered series carries its `line`. `Contract.Debt` names the `balance` field role; a pack rule fills it and a machine's `on enter retired { set balance = 0 }` extinguishes every field that plays it (stage 6). Not yet: the option grammar aligned with `Contract.Option` (stage 7) — `docs/40` §10 |
| `stream` (owner, direction, currency, amount, active when) | ✅ | bare native expressions. An unrecognized item in the body is rejected (`E0004`); it used to be bumped and discarded, so `payment net 60 days` on its own line — and every typo'd key — compiled clean and did nothing |
| `stream ... { category <path> }` | ✅ | what the stream IS, economically — a dotted path into the cash flow statement (`operating.deduction.abatement`). Aggregation reads this rather than pattern-matching the stream's name. Must name a category the active pack declares (`E5022`); the pack's own vocabulary must be rooted in `operating`, `investing` or `financing` |
| `schedule on <date>` | ✅ | settles on its own date, undiscounted for the period it lands in |
| `schedule every <interval> from .. to ..` | ✅ | `day`, `week`, `month`, `quarter`, `year`. Distinct from the calendar cadence: a stream may pay quarterly on a monthly grid |
| `schedule <on \| every> ... [start\|mid\|end]` | ✅ | one placement axis, three positions, at most one. `start` is an annuity due (interval's start), `mid` halfway, `end` its close. A recurrence defaults to `end` (ordinary annuity), a one-shot to `start`. See `12_payment_timing.md` |
| `schedule on phase_enter(..)` / `every .. phase_start()/phase_end()` | ✅ | |
| `schedule ... on day <n>` | ✅ | places the payment within its interval, clamped to the month's length |
| `contract ... payment net <n> [days\|months]` | ✅ | applies to every stream the contract lowers; billing at period close, due date rolled |
| `schedule ... net <n> [days\|months]` | ✅ | overrides the contract's terms for one stream; rejected on `schedule on <date>` |
| `schedule ... on eom` | ✅ | last day of the month; 28 February, not 30 |
| `schedule ... on <weekday list>` | ❌ | rejected; removed from the grammar |
| `schedule ... convention <roll>` | ✅ | following/modified_following/preceding/modified_preceding |
| `schedule ... calendar "<name>"` | ✅ | weekend, us, target, uk (computed holidays) |
| `schedule ... except [dates]` / `also [dates]` | ✅ | roll-adjusted point dates |
| `schedule ... stub <policy>` | ❌ | rejected with a diagnostic and removed from the grammar. It was previously accepted and discarded, so a model could ask for a stub period and silently get a full one |
| `event <name> [schedule <expr>] [when <expr>] { actions }` | ✅ | fires on EACH OCCURRENCE (`docs/34` D1). A schedule supplies the occurrences and `when` filters them; with no schedule an occurrence is the condition's rising edge — true having been false, re-arming when it falls. At least one clause is required. There is no `once` keyword and nothing latches: once-ness is declared, as a singular schedule or a topology with no way back. The schedule is the same sub-language a stream's is, `state_enter` included. Conditions evaluate once per period in declaration order; the guard reads state as the period OPENED and series STRICTLY BACKWARD (`docs/28` §4), with same-period and forward reads refused (`E1134`). |
| — `set entity <ref>.<field> = <expr>` | ✅ | visible as `entity.<field>` on the owner and `<family>.<entity>.<field>` from anywhere. An entity whose type declares a lifecycle opens in its declared initial state rather than null. Every write is published in `deterministic.transitions` |
| `deterministic.journal` | ✅ | every causal act, with what became of it: `applied`, `declined`, `overridden`, `ignored`, `failed`. Answers what the model DID, where `transitions` answers which fields changed — an action that changed nothing appeared nowhere before, so an `activate stream` losing to the stream's own `active when` left no trace. Waterfall steps carry the pot before and after, making a short pot visible as the reason a payee was underpaid. Omitted when a model has no events, options or waterfalls. See `docs/28` §8 |
| — `activate/deactivate stream` | ✅ | persists forward |
| — `activate/deactivate contract` | ⬛ | **retired** (backlog 7.73). A contract is a collection of streams and one switch cannot say what forbearance says; the replacements are a lowered stream by name (7.50) or `active in state` |
| — `exercise option` | ✅ | forces the option's own ELECTION at the firing period. It does not bypass `exercisable in`: an option outside its window is not one anyone holds, and forcing one warns and declines |
| `option <name> [on entity <ref>] type <t> [exercisable in <phase>] { parties / exercise when / payoff }` | 🟡 | an option is a contract with an election, so it carries an owner and parties. `exercise when` reads entity fields by qualified path and its owner's entity state, as the period OPENED; it cannot read a stream. Rule-based exercise only — optimal exercise is out of scope for v0.1. Every declared option publishes a series, zero where it did not exercise |
| `run deterministic` / `run monte_carlo trials N seed N` | ✅ | honoured by the engine; an explicit run config still wins. A trial publishes the SAME metric map the deterministic block does — `model.*`, `domain.*`, `metric.*` — and `monte_carlo.metrics` summarises each name across the trials, p01 through p99, stating the `trials` count it was taken over (backlog 7.87). Per-trial series are not retained |
| Literals: `money_lit` (`42000 USD`), `list`, `map_inline` | ❌ | rejected |
| `terms { k = <literal> }` | ✅ | one literal per term; trailing tokens are rejected (`E0004`) rather than discarded |
| `terms { k = inputs.<name> }` | ✅ | defers to a declared input, so scenarios and Monte Carlo drive it. Unknown input → `E5010` |
| Expressions (`cfdl-calc` dialect) | ✅ | see docs/03; decimal-first, excel_compat mode |

## Tooling status

- `cfdl parse <root>` dumps the typed AST as JSON (spans included).
- Parser robustness: deterministic fuzz tests (random soup, mutation, and
  truncation sweeps) assert lex+parse never panic; run in normal `cargo test`.
- `cfdl-validate` has per-code unit tests derived from the invalid fixtures.
